# Code Review Checklist



**CSC-154 Software Development - Fall 2026**



Use this checklist when reviewing Pull Requests before changes are merged into `main`.



## Branch and Pull Request



- [ ] Changes were made on the appropriate branch, not directly on `main`.

- [ ] Branch name follows the naming convention required by the assignment.

- [ ] Pull Request targets `main`.

- [ ] PR title clearly describes the change.

- [ ] PR description explains what was changed and why.

- [ ] If the work is Issue-driven, the PR references the related Issue using `Closes #`, `Fixes #`, or `Resolves #`.

- [ ] The PR contains only changes related to the assigned work.



## Quality



- [ ] The change meets the assignment or Issue requirements.

- [ ] Code or documentation is clear, organized, and professional.

- [ ] There are no obvious errors, unnecessary files, or unrelated changes.

- [ ] Documentation is updated when the change affects instructions or workflow.



## Testing and Verification



- [ ] The author explains how the change was tested or verified.

- [ ] Code changes run correctly or pass available tests.

- [ ] Documentation changes were reviewed for accuracy, formatting, and working references.

- [ ] Issue acceptance criteria have been checked when applicable.



## Security



- [ ] No passwords, API keys, credentials, or other secrets are committed.

- [ ] No unnecessary sensitive information is included.

- [ ] Code changes do not introduce obvious unsafe behavior.



## Peer Review



- [ ] Reviewer examined the **Files changed** tab.

- [ ] Feedback is specific, respectful, and constructive.

- [ ] Reviewer identifies both strengths and necessary improvements.

- [ ] Author responds to requested changes.

- [ ] Revisions are pushed to the same branch and PR.



## Before Merge



- [ ] Requested changes have been addressed.

- [ ] No unresolved merge conflicts remain.

- [ ] Required review or approval has been completed.

- [ ] Verification is documented.

- [ ] PR is ready to merge into `main`.



## After Merge



- [ ] Related Issue is closed when applicable.

- [ ] Branch may be deleted after successful merge.

- [ ] Relevant documentation reflects the completed change.



## AI-Generated Content



If AI tools such as GitHub Copilot are used:



- [ ] AI-generated content has been reviewed by a person.

- [ ] Suggestions have been checked against the actual repository requirements.

- [ ] Incorrect, irrelevant, or unnecessary AI-generated content has been removed.

- [ ] AI output is not considered complete until it has been verified.



## Review Standard



Review the work, not the person. Feedback should help improve the project while maintaining professional communication.
